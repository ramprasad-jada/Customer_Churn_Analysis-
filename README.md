# Customer Churn Analysis

A MySQL + Python + Streamlit project that stores subscription data, measures customer churn, and ranks active customers by churn risk.

> The bundled data in `data/` and `database/seed_data.sql` is **synthetic** (generated by `src/generate_data.py`). Replace it with real data before drawing business conclusions.

## What it does

1. **Database** - 7 MySQL tables: customers, plans, services, subscriptions, payments, support_tickets, churn_records.
2. **SQL analysis** - churn rate by plan, city, age and gender, churn reasons, tenure, failed payments, support tickets, monthly trend, revenue impact and a rule-based at-risk list.
3. **Machine learning** - logistic regression and random forest compared with cross-validation against a majority-class baseline.
4. **Dashboard** - filters, KPIs, segment charts, payment and ticket analysis, and a model-scored risk watchlist.

**Churn definition:** a customer is churned if `churn_records` has a row with `churn_status = 'Churned'`. `At Risk` rows are still-subscribed customers flagged as likely to leave.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env          # then put your own MySQL password in .env
```

**Without MySQL:** skip the database steps. The app and notebook read the CSV files in `data/` automatically.

**With MySQL (8+):**

```bash
mysql -u root -p < database/schema.sql
mysql -u root -p < database/seed_data.sql
mysql -u root -p < queries/03_churn_analysis.sql
```

Create the `churn_user` account (or change `DB_USER` in `.env`) and grant it access to `customer_churn_analysis`.

## Run

```bash
python src/train_model.py          # trains models, writes metrics + risk scores
python -m streamlit run app.py     # dashboard
python tests/test_analysis.py      # data and feature checks
python tests/check_churn_sql.py    # runs the churn SQL on the CSVs via SQLite
python tests/smoke_app.py          # dashboard code path check
```

## Results on the bundled synthetic data

Overall churn rate is 33% (99 of 300 subscribed customers). Basic-plan customers churn most (about 48%), Premium least (about 22%), and customers with several support tickets churn more often.

The model is only modestly predictive: cross-validated ROC-AUC is roughly 0.69-0.70 for both candidates, against 0.50 for the baseline. The held-out test set has only 60 customers, so its AUC (0.58-0.62) is noisy. Tenure and payment counts are excluded as features because they leak the outcome.

## Known limitations

- Synthetic data: findings describe how the data was generated, not real customer behaviour.
- Small dataset: segment-level rates (for example by city) are based on few customers.
- Risk scores use balanced class weights, so treat them as a ranking, not true probabilities.
- Snapshot design: there is no history of when customer attributes changed, so this is not a true time-based prediction.
- `schema.sql` was reconstructed from the columns used in your queries. If your real tables differ, adjust it.
